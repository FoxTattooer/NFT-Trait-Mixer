# v0.7.0

- New supplied crowned avatar on black background is used for apple-touch-icon, manifest icons, favicon and app header. New versioned URLs plus legacy aliases.
- Production startup reads only the saved manifest and asset keys. PNG Blobs are fetched for the current composite and visible thumbnails; thumbnail I/O is limited to two jobs, with IntersectionObserver when supported. Object URLs are revoked for detached thumbnails and after painting.
- After a durable save, matching image strings in current state and history are replaced by internal asset references. Unchanged history remains reversible; images referenced by current/undo/redo are pinned. Obsolete unpinned assets are reclaimed on a subsequent save. The database format is unchanged, and inline legacy projects remain readable.
- Internal references are accepted only for trusted storage hydration, never arbitrary imported JSON. JSON backup resolves image bytes one trait at a time into Blob parts. ZIP resolves its PNG and JSON entries too. Exported files remain portable.
- Drag autoscroll uses a depth-dependent curve up to 1250 px/s, timestamp-based distance, viewport clipping and fixed bottom-navigation exclusion. Nested scrollers have priority and hand off at their boundary. Drop, cancel, Escape, lost capture and blur terminate scrolling. Unchanged drop markers are not rebuilt each frame.
- Added mint hover, pressed, focus, selected and drag/drop styling. Hover lift is limited to fine pointers; reduced-motion preference removes transitions/transforms.

Validation: full npm suite including new lazy storage and UI tests. 610-image lazy startup makes zero image-record reads and zero Base64 conversions. Tests cover selected-image pixel rendering, URL cleanup, metadata saves, deletion/undo, portable JSON and ZIP, missing asset rollback, chunked wrapped Base64, edge-dependent scroll speed, middle-zone stop, upward scroll, nested-boundary handoff, and frame cleanup.

One-run 610-image / 153 MiB stress probe in Node with fake-indexeddb: initial save 0.87 s, metadata save 0.03 s, lazy restore under 0.01 s; compatibility eager restore 0.45 s. Process RSS stayed about 710 MiB across lazy restore versus 1182 MiB after the compatibility eager restore. This runtime includes fixture and in-memory database copies. These numbers are not physical iPhone measurements and are not memory guarantees. The user PSD and device were not available. Large ZIP exports still collect the archive contents; legacy inline restore still reads the legacy record until it is saved in the newer format.
